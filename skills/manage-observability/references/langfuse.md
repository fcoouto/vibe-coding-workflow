# Langfuse preparation

Load only for selected Langfuse setup, status or forwarding questions. Follow the common procedure for authorization, payload scope and evidence; this reference adds only provider-specific preparation.

## Select a destination

Identify the user's Langfuse Cloud region or self-hosted destination and intended Langfuse project. A workflow Project is not automatically a Langfuse project. Several selected workflow Projects may share one authorized destination with qualified Project/Repository filters; separate destinations retain their access boundaries and separate dashboard links.

Langfuse is the first planned provider. This package does not yet implement its persistent settings, credential connection, collector or exporter. Do not request API-key values, contact a destination, send a test trace or write credentials merely to prepare the proposal. Name a supported secret-store reference only when actually known; otherwise leave that prerequisite pending. Never paste credentials into chat, Git, a report or a destination URL.

When a supported setup owner becomes available, use current Context7 or official Langfuse documentation for the selected client/version and destination. Do not assume an installed SDK, account connection or synthetic probe qualifies the actual workflow. Completion needs explicit Project opt-in, authorized payload/destination handling and qualified source collection; the existing source qualification order, including prior repository-gate proof for D9b and a real native-only coordinator/worker/reviewer measurement case, remains intact.

## Source coverage and forwarding

OpenRouter Broadcast observes OpenRouter-routed requests only. Native coordinator/worker and local-model measurements require their own qualified sources; do not reroute them for visibility. Qualify the actual connector's request identity and correlation fields rather than inferring support from API documentation or matching by timing.

Broadcast destination filtering, sampling and privacy settings are independent of Langfuse SDK controls. Verify authorized source-side scope and the actual exported metadata; a privacy-mode checkbox alone does not prove the payload is safe. Do not enable account-wide forwarding to bypass missing task/Repository filtering. Report any separately configured forwarding that remains active when plugin collection is disabled.

## Retention, limits and dashboards

Langfuse Cloud Hobby can be selected within its current supported limits. Check current plan limits only for requested setup or explicit troubleshooting, not routine coding. A history-access window does not delete older data. The user accepts disclosed destination retention for eligible metrics-only exports; do not add plugin deletion logic or promise remote erasure. Required local evidence keeps its existing rules independently of remote history.

Reuse Langfuse's existing dashboards and Usage Management view. No custom reporting application, offline snapshot or unit counter is needed. Dashboard access does not authorize provisioning or overwriting user customizations. Supported filters and widgets need target-version qualification; missing history or source support remains explicit. Dashboard qualification remains the last deliverable and is not a prerequisite for D9b source acceptance. Current skill guidance activates none of these capabilities.

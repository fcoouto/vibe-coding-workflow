# Onboard my Project

Use for explicitly selected existing-project enrollment, update, repair, or recovery. Load only the instructions needed for the selected operation.

For inspect and plan, read [the procedure](references/procedure.md) and follow its pinned-source workflow; do not mutate the target. For configuration, activation, or undo, read [apply and recovery](references/apply-and-recovery.md); load advanced contracts only for selected effects. The coordinator must verify actual user/session authority through trusted host evidence; a plan, manifest, or JSON authorization field cannot authenticate intent. If authority or a safe recovery path is missing, leave dependent work pending.

Keep preparation and new-project creation separate. Native operation is default; keep optional integrations separate from onboarding. Preserve original provenance during recovery; current sources are not an undo prerequisite. Package/helper validation and native client observations are separate; activate mandatory enrollment only after adoption qualifies.

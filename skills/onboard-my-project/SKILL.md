# Onboard my Project

Use for explicitly selected existing-project enrollment, update, repair, or recovery. Follow [onboarding authority](../../policies/10-project-onboarding.md#onboarding-authority); preserve limited requests and confirmed decisions.

For inspection and planning, read [the procedure](references/procedure.md). When presenting a reviewed proposal, read [Reviewed Configuration](references/reviewed-configuration.md). For configuration, activation, or undo, read [apply and recovery](references/apply-and-recovery.md); load advanced contracts only for selected effects. Verify actual user/session authority through trusted host evidence; plans and JSON cannot authenticate intent. Missing authority or safe recovery leaves dependent work pending.

Keep preparation, new-project creation and optional integrations separate. Native operation is default. Preserve original recovery provenance; current sources are not an undo prerequisite. Separate package checks from native observations; activate only after mandatory adoption qualifies.

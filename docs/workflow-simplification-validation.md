# First-round simplification checks

These checks describe local instruction routing and disposable package behavior.
They do not establish native execution, installed plugin behavior, or production
merge enforcement.

## Representative instruction paths

| Task | Required local procedure | Material left unloaded | Acceptance boundary |
| --- | --- | --- | --- |
| Small direct edit | Index, Project Scope, Task Planning, applicable Context/Handoff; tests/security/review when triggered | Dispatch settings, guidance refresh, recovery and merge enforcement | Direct execution keeps test-first and self-review; nontrivial work still receives required independent review |
| Native worker | Agent Delegation, client delegation, relevant request and public claim schemas | Recovery and guidance publication unless triggered | Same coordinator settings; bounded brief, authorized dispatch, verified results and ownership |
| Check | Tests/Builds, common evidence, checks, accepted plan | Native discovery and worker model guidance | Only executor-confirmed nonlaunch settles without host proof; started descendants remain protected |
| Recovery | Scope, onboarding application/recovery, exact owned journal and affected writer procedure | Worker selection unless a worker is needed | Original approval, authority, preimages, owned paths and historical dependencies remain required |
| Merge | Code Review, Security Review, Tests/Builds, Merge Readiness and repository gate | Setup catalogs and unrelated integrations | Local completion never substitutes for the actual repository-controlled gate |

The policy index now carries the direct-execution decision. Task Planning carries
the complete test-first/self-review requirement. Failure and stalled-work triggers
still load delegation's escalation procedure. Reconciliation and guidance refresh
now have public field references; ordinary requests need no implementation read.
Setup still assesses the full pinned Toolkit catalog and every contract.

## Supported boundaries

- Managed execution still requires its exact accepted policy/runtime pins; records
  are never repinned. Basic guidance uses current client/index availability,
  physical membership and accepted shared dependencies, with package hashes kept
  as provenance rather than an update blocker.
- Finite foreground completion releases cooperative capacity while preserving the
  actual exit code. It never releases assignment or writer ownership or proves
  stopped descendants. Known background services and timed-out commands retain
  capacity; independent phase release requires its durable execution receipt and
  existing reconciliation proof.
- File recovery still discovers retained stores to protect historical dependencies.
  It narrows affected owners and ignores unrelated membership status, rather than
  assuming an unreadable store contains no writer. Runtime-bearing membership
  changes retain existing-store admission when another member is active.
- Onboarding derives repeated observed identities and hashes in schema-2 proposals.
  Semantic decisions, full catalog coverage and exact D4 approval remain explicit.
- Existing historical readers, provenance formats and recovery genealogy remain. Completion and ownership checks share one validated ledger observation within each transaction. Broader provenance-graph redesign remains outside this first round.
  Artifact publication no longer initiates unrelated retention scans.

results, independent review findings and unresolved native limits are recorded in
the implementation plan. The complete 41-module run covered 874 test executions;
its findings required runtime boundary fixes and one existing assertion update.
All six affected modules then passed (140 test executions, including the new
completed-phase cancellation regression). The other 35 modules passed in the
complete run; a second full-suite pass on the corrected source is not claimed.
Final package validation and diff checks passed. Native execution remains
unchecked.

The small direct-task reading path fell from 3,924 to 2,654 words (32.4%). This
static path count excludes later applicable testing, security and review contracts;
it is not a measured token or latency saving.

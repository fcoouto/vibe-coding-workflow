# Pilot readiness

Working coordination plan, 3 November 2026. Baseline: reviewed main `a9d5a47` (PR55).

The user adopted the minimal default workflow after an independent whole-project audit. Basic onboarding provides useful project guidance and commands without requiring a runtime database, task-state patch blocker or repository enforcement. Native operation remains the default. OpenRouter and Langfuse are optional.

## Completion boundaries

Basic onboarding inspects relevant project instructions and configuration, assesses the complete Toolkit component catalog, applies authorized changes recoverably, and reports relevant checks, limitations and an undo location. Optional capabilities do not prevent completion. Large unrelated files and missing optional integrations are not onboarding prerequisites.

Ordinary development uses native editing, tests and proportionate independent review. Managed execution, scheduling, external models, telemetry and merge enforcement acquire only the prerequisites for the selected feature. Preserve existing repository protections and explicitly selected enforcement. Unknown observations never become passing evidence.

The overall self-host pilot goal still requires actual applicable native, recovery and selected merge-enforcement evidence. Package tests alone do not establish client behavior. Source implementation does not authorize installation, hook trust, credential access, transmission, native qualification runs or repository-setting changes.

Implement and review small coherent slices in this order. Disable/recovery work and instruction updates may proceed alongside the first code slice when files and mutable resources are disjoint. Review each wave before releasing dependent work. Merge completed slices into `main`; do not accumulate another integration branch.

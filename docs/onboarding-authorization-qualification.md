## Unresolved runtime delivery

`startup.acquire_project_entry` accepts an internal trusted reader; production entry supplies none. `changes._scoped_qualification` validates supplied observations but does not obtain their truth. The native adapter reads thread provenance and review content, while `doctor.discover` reads hook definitions/trust. Neither proves execution in the selected client.

Read-only schema generation from the installed Codex CLI exposes `HookStartedNotification` and `HookCompletedNotification`. These provide live thread/turn-bound execution summaries, not an implemented durable onboarding qualification source or current-control/history reader. The reviewed thread-read schema exposes hook prompt fragments, not retained complete hook-run summaries. Protocol availability does not prove that a particular client emitted or obeyed those events.

The remaining implementation needs actual owner-observed required behavior, exact project/checkout/client/candidate binding, bounded durable lookup, cheap current-control invalidation, and reliable prior-active history. An editable configured flag cannot establish that history. Existing transaction records prove their own operation, not completeness of all prior activation history. Do not manufacture a receipt, create a signer/registry, widen a native campaign, or claim that this merge resolves these gaps.

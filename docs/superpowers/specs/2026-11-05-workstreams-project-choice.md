# Workstreams project choice

The user wants one Enabled/Disabled choice during onboarding and through the
Workstreams skill. Repeated requests to enable it must not lead to a managed
runtime activation campaign.

Save one checkbox in an owned section of the selected checkout's `AGENTS.md`.
Enabled means suitable automatic cooperative native coordination. Disabled stops
optional future coordination; explicit delegation, required review and existing
child reconciliation remain available. Existing worker selection, permissions,
ownership, budgets, verification and naming requirements still apply.

Onboarding and the skill use the same procedure and effective instruction block.
Submitted answers take effect immediately after a recoverable edit and readback.
Repeated settings are no-ops. Missing or conflicting choices remain unconfigured.
Status reads guidance without creating runtime state. Linked checkouts receive
changes only through normal instruction inheritance or Git integration.

Resource admission and capacity recovery retain their independent advanced
controls and prerequisites. The checkbox changes neither. Selected protections
cannot be bypassed, and unknown ownership remains reserved.

Implement through existing native instruction editing. No new runtime schema,
settings service, dependency, qualification, VM or Docker work is needed.

Acceptance: exercise onboarding with Enabled and Disabled, skill status and
toggles without a runtime, repeated enable, preservation of unrelated guidance,
required review while disabled, and explicit advanced-control routing. Obtain
independent Astra review and run package validation. Report instruction behavior
separately from observed managed execution.

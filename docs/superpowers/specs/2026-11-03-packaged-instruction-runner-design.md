# Packaged instruction runner

The user approved replacing repeated generated loader code with one fixed packaged runner, including an extra helper command for small selections. This supersedes only the previous single-batch/no-helper optimization. Automatic draining and all delivery checks remain required.

## Approach

Keep the existing `read_instructions.py --helper` envelope and fixed, contained, runtime-pinned `scripts/drain_instructions.js`. The short Codex launcher loads that helper once per selection, verifies successful terminal execution and the complete versioned helper envelope, then evaluates only its trusted code. It invokes `drainInstructions({root, paths, external, exec, emit})` and returns the final receipt.

Move command construction, instruction-envelope validation and the first read from the Codex template into that runner. Reuse its existing awaited continuation loop. Every selection now has one helper command plus its existing reader commands; a small selection has one helper and one reader. No combined code/data envelope, cache, automatic scope grouping, new tool, hook, server or dependency is introduced. The project-independent reader remains behind the Codex adapter.

Alternatives considered: the conditional code envelope adds protocol and clipping complexity to avoid a local helper command; grouping known applicable files reduces some calls but retains repeated generated code. The user selected the fixed runner and accepted its small-load cost.

## Preserved requirements

Preserve exact Unicode/line endings; 8,000-byte source sections, 9,500-byte pages and 24,000-byte batches; manifest/path/hash/target checks; separate package and external selections; fixed page order, revision, total and mode; complete positive character counts; bounded small-page recovery without replay; awaited notifications and terminal completion. Changed sources, cancellation, unfinished children, invalid metadata, failed notification or unrecoverable clipping cannot report success. A yielded outer cell must finish before task work proceeds. Instruction text and footer commands never become executable code.

RTK, other plugins, model, reasoning and native authentication remain unchanged. Existing plain reader APIs and other clients are unchanged. No merge or live installation is selected.

## Proof

Execute the actual shorter launcher and packaged runner through the existing real-reader tests. Retain failure cases and add malformed/unfinished helper probes, since helper loading now precedes every instruction read. Review the cohesive diff independently. Run focused reader/drain/startup/package-compatibility tests and package validation, retaining the known unrelated state-test limitation.

Qualify exact native delivery for a small selection, the original Graphify selection, a maximum batch, forced clipping and early yield. Run one fresh paired implementation/review/resume benchmark against `1fc4dfa`, with unchanged prompts and strict external-state guards. Audit selected-source delivery independently; report repeated generated bytes, normalized tokens, model/tool calls and elapsed time separately. Stop on drift or timeout; do not retry automatically or claim savings from incomplete delivery.

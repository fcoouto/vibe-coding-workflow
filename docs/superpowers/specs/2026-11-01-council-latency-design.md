# Council latency

Approved scope: reduce dispatch, packet forwarding and verification overhead while
preserving maximum supported reasoning, the 1200-second session and cumulative
600/360/240 phase allowances. Free remains disabled.

The Frontier pilot spent about 184 seconds outside its critical external calls and
fresh native synthesis. Opus's successful investigation generated for 435 seconds;
its critique exhausted the original phase deadline without terminal text. Those
observations justify improving coordination, not claiming a provider root cause.

## Approach

Use the existing runtime, private records and native host controls. Text native
packets return the complete deterministic prompt and its SHA-256, assembled from
verified phase evidence and anonymous observations. Forward it unchanged into a
fresh native child; the host still owns actual model, effort and stop observations.
Repository mode retains independent read-only inspection.

Record packet issuance and verification times in existing member records. Retain
local launch/response/stop events in existing worker progress. These wall-clock
observations explain latency; monotonic deadlines remain authoritative.

Dispatch ready seats within observed capacity, collect completion events, verify
each terminal report promptly, and advance only after all owners are settled.
Benchmark comparisons and billing reconciliation stay outside live deliberation.

Streaming and deadline redistribution are deferred. No new service, automatic
semantic acceptance, prompt summaries, model probe round or telemetry export.

## Proof

Controlled tests cover exact Unicode evidence and peer reports, no identity leaks,
repository isolation, deadline/cancellation behavior, nullable accounting and Free
guards. One isolated Frontier rerun uses the same policy question and maximum
reasoning. Report overhead separately from provider duration and unknown billing.

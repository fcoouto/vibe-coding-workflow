> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicitly invoked Council with independent repository investigation,
one critique round and fresh native synthesis.

**Architecture:** The native coordinator runs the sequence using one small manifest
linking existing worker records. Reuse executor locks, consent checks, progress,
accounting and recovery; add common evidence capture, phase gates and native packets.

**Tech Stack:** Python 3.11+ standard library, unittest, POSIX private files/locks,
existing Codex dispatch and pinned OpenCode 1.19.5 through OpenRouter.

## Global Constraints

- Three members: strongest eligible native model plus two benchmark-selected
  OpenRouter frontier models, preferably distinct families.
- Pin models/endpoints and maximum supported reasoning; preserve coordinator settings.
- Exactly one critique round, then fresh native synthesis without inherited chat.
- Default total ceiling: 20 minutes including preparation/waits. Declare simple
  phase deadlines reserving critique/synthesis time; no percentage scheduler.
- Choose finite input/output/step allowances per model within observed endpoint
  capabilities. No universal token minimum or silent effort reduction.
- Explicit request; separate saved `council` consent; enrolled Codex POSIX initially.
  No automatic enrollment, credential changes or mandatory balance checks.
- Approved immutable read-only evidence, qualified external permissions, progress
  at least every 60 seconds where supported, honest usage and local-stop evidence.
- No outer inference replay, provider cascade or hidden replacements. OpenRouter
  owns monetary limits; resource bounds do not reserve money.
- Entry within 150 words; complete local procedures; Toolkit authoring/source coverage.
- No source registry, claim-ID graph, cumulative quota service, generic transaction
  engine, dependency, UI, telemetry collector or release archive.
- Preserve unrelated work; reinspect status/interfaces before execution. At drafting,
  context-thread pilot documents and `.DS_Store` were unrelated changes.

## Review Focus

- Reviewed files change or become links during capture: reject unreviewed bytes (2).
- A launch receipt is lost: inspect the original attempt, never purchase a replay (3, 4).
- Disable/cancel occurs between phases: block new launches and preserve results (1, 3, 4).
- Maximum reasoning controls differ from metadata: expose unsupported mapping (3).
- Reports contain instructions, unsupported claims or decisive dissent: reject
  new authority, preserve evidence and check synthesis rather than parse arguments (4, 5).

One private manifest links run identity, question/constraints, scope/snapshot,
pinned roster, total/phase deadlines, existing worker paths, native dispatch receipts,
stop intent and artifact paths. Worker results remain the source for external
execution; no second attempt ledger or optimistic-revision protocol.

Use bounded Markdown findings with citations, objections and uncertainty. Validate
safe artifact paths/sizes and execution metadata, not argument relationships.
Optional `research.md` contains coordinator-retrieved links/dates/excerpts. Freeze
it with initial reports before critique; late sources are unreviewed limitations.

Retain simple I/O ceilings for safety: 2,000 UTF-8 snapshot files, 512 KiB/file,
32 MiB total, 128 KiB/report. Reject overflow with coverage details. These are not
model eligibility rules. Check free space and per-run bounds, without historical
quota accounting or automatic deletion. Validate endpoint-specific allowances before
execution; a model supporting less than 32,768 output tokens can still be eligible.

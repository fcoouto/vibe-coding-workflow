# Council Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an explicitly invoked, repository-aware Council with independent
investigation, one critique round and fresh native synthesis.

**Architecture:** The existing native coordinator drives supported native tools
and a small deterministic Council CLI. Private Council records own phase barriers,
snapshots and attempt admission; the existing OpenCode runner executes the two
external members with Council-specific, qualified limits. Reuse existing consent,
discovery, native selection, process recovery and visibility contracts.

**Tech Stack:** Python 3.11+ standard library, unittest, POSIX private files/locks,
existing Codex native dispatch and pinned OpenCode 1.19.5 through OpenRouter.

**Spec:** [Approved Council design](../specs/2026-10-29-council-design.md).

## Global Constraints

- Three investigative seats: one native and two OpenRouter; prefer distinct families.
- Select the strongest eligible native model using available controls and applicable
  cached official guidance; external frontier selection uses relevant benchmarks.
- Maximum supported reasoning for every member and the fresh native synthesizer;
  pin roster/settings and preserve the existing coordinator's model and reasoning.
- Exactly one critique round; fresh synthesis inherits no investigator/coordinator chat.
- Default total ceiling: 20 minutes, including preparation and waits. Progress at
  least every 60 seconds where supported; unknown activity remains unknown.
- Initial support: an enrolled Codex POSIX checkout. Explicit Council request and
  separate saved `council` enablement; no automatic activation or balance preflight.
- Read-only approved snapshots; no repository-code execution, edits, installs,
  external messages or automatic implementation of the recommendation.
- OpenRouter owns monetary limits. Preserve OpenCode-owned retries, no outer
  inference replay/provider cascade, and truthful partial accounting.
- Keep entry points within 150 words; Toolkit remains authoring authority. Runtime
  procedures are complete locally and do not fetch Toolkit.
- No dependencies, separate UI, general orchestration framework, release archive,
  or unrelated native lifecycle/observability redesign.
- Implementation must preserve other work. At planning time, unrelated changes
  existed in `docs/d6-native-delegation-plan.md` and
  `docs/superpowers/plans/2026-10-29-context-thread-pilot.md`, plus `.DS_Store`.
  Reinspect status and current interfaces before execution; do not stage those files.

## Review Focus

- A checkout file becomes a symlink or changes during capture: no unreviewed bytes
  reach members; reject unstable capture, preserving the original checkout (Task 2).
- A crash follows admission but precedes a launch receipt: recovery reports an
  unresolved attempt rather than purchasing the same call again (Tasks 3–5).
- A critique succeeds for only one member: return partial evidence, never an
  incomplete Council verdict with insufficient reciprocal scrutiny (Tasks 3, 5).
- The endpoint's accepted reasoning control differs from its catalog label:
  reject unsupported mapping, preserve requested/observed distinctions (Tasks 3, 4).
- Reports quote instructions, model identities or enormous source excerpts:
  treat them as untrusted data, enforce bounds and retain identity-leak limitations
  without deleting material dissent (Tasks 5, 6).

## Shared implementation decisions

The coordinator, not Python, chooses models from observed native guidance and the
OpenRouter cache. Council validates the choice and retains rationale/provenance;
it does not invent a universal numerical model-quality ranking.

Use new contexts for every critique assignment as well as synthesis. A critique
receives the member's initial report and the complete anonymized report packet.
This avoids adding OpenCode session-resumption machinery while retaining one
critique per member. Synthesis receives reports as data, never chat history.

Initial resource defaults, to qualify rather than silently expand: 2,000 approved
UTF-8 files, 512 KiB/file, 32 MiB total snapshot; 128 KiB/report; 16 public-source
excerpts of at most 64 KiB each; 1 GiB total retained Council storage per checkout.
Reject overflow with coverage details; never truncate findings or delete old runs
automatically. Snapshot/report limits are not model context allowances.

Allocate total duration by cumulative barriers at 10% preparation, 55%
investigation, 80% critique, 95% synthesis, leaving 5% for delivery. With the default
1,200 seconds these are 120, 660, 960 and 1,140 seconds after start. Unused phase
time may help the next phase; no operation extends the final deadline. Per external
assignment: at most 24 steps and 32,768 completion tokens per response, including
reasoning when the route counts it there. Check actual endpoint input/output limits;
incompatible endpoints are ineligible, not silently downgraded. These are finite
caps, not promises of completion or a dollar allowance.

Create run records with `version`, `run_id`, `revision`, `checkout`, `scope_id`,
`question`, `constraints`, `approval_ref`, `started_at`, `deadline`, `phase`,
`snapshot_digest`, `roster`, `sources`, `attempts`, `limitations` and `artifacts`.
The three stable seat IDs are `native`, `external-1`, `external-2`; synthesis uses
`synthesis`. Each roster entry stores model, family, route, endpoint (external
only), supported/requested effort, discovery/guidance references, selection reason
and execution qualification. Store true identities outside anonymized packets.

Actions use bounded JSON dictionaries, not an open-ended event framework. Mutations
require `expected_revision`; attempts use a stable `(run_id, phase, seat)` identity.
Statuses distinguish prepared, admitted, running, succeeded, failed and unresolved.
Native coordinator observations are recorded as such, not authenticated proof.
